# 从 CyberStrikeAI 借鉴（门控 / 记忆 / 治理）· 2026-10-10

> 来源＝本机 WSL 部署的 `CyberStrikeAI`（`docs/zh-CN/*.md`，HEAD `deda642`）。**只取其设计思想，不引入其依赖**。
> 用途：对照改进我们自己的**门控（akasha-gate）/ 记忆（阿卡夏）/ 观察口径**。

## 一、它做对了、而我们可以直接学的（门控）

| # | 它的做法（原文要点） | 我们的现状 | 建议 |
|---|---|---|---|
| **B1** | **规则有序，「首先命中的启用规则决定提醒」**；规则可单独启停 | 我们的门控是**硬编码的若干正则**，无顺序、无开关粒度 | 把门控规则做成**有序列表**（每条可启用/停用、带名字），判定＝首命中 |
| **B2** | **检查对象不只原文**：工具名 + **参数的 JSON 表示 + 嵌套字符串与键名 + 最多三轮 URL 百分号解码** | 我们**只看命令原文** ⇒ **编码/嵌套绕过能骗过我们** | 判定前先做：`decodeURIComponent` **≤3 轮**，并遍历参数的**键与值**（不只值） |
| **B3** | **提醒模板带 `{match}`**（或命名捕获组 `(?P<match>…)`），命中后返回**可读提醒**给 agent，而不只是"拒绝" | 我们的拒绝信息是固定中文说明，**不带命中片段** | 拒绝/提示文案带上**命中的具体片段** ⇒ 对 agent 更有教育性（且能回灌 C1 的坑提示） |
| **B4** | 命中后**界面与执行记录用独立的「已拦截」状态**，保留原因；**监控单独统计拦截次数，不计入调用失败或成功率的分母** | **我们今天就修了这个**（门控拒绝曾被计入任务失败，灌水漏召率） | ✅ 已是同一结论 ⇒ 把"**守卫拦截独立于成功/失败口径**"**写成明文设计原则**（写进口径文档，防复发） |
| **B5** | **试匹配（dry-run）**：未添加的规则可先**校验/试匹配**再入列表；校验失败定位到字段 | 我们**没有**试匹配 ⇒ 今天为一条假阳性来回折腾 | 给门控加 `--dry`：给一段命令**只报命中、不拦截**（调试假阳性/回归的利器） |
| **B6** | **默认保护**：老配置没有 `tool_guard` 也默认开启「政府域名保护」 | 我们默认开（门控常在）✓ | 保持；并学它**对旧配置的兼容判定** |
| **B7** | **权限与审计**：查看/试匹配需 `config:read`；修改需 `config:write`＋全局范围；**规则变更写系统审计日志** | 我们改了规则**没有审计线** | 门控规则变更**落审计线**（谁改的、改了什么、何时） |
| **B8** | **诚实边界声明**（原文）："这是文本规则防护，**不能代替目标授权或网络隔离**"；并逐条列出**守不住的**（仅 IP 表示、DNS 别名、重定向、文件内目标、混淆编码；且**只覆盖经本应用 MCP 入口的调用**，直接终端/子进程绕过） | 我们有零散边界（如 WSL 路径），**没有成文清单** | 照这个写法，把我们的**边界清单**写全（放进 INSTALL/门控文档）：**我们守不住什么** |

## 二、记忆与治理层可借鉴的

| # | 它的做法 | 我们的对应 | 建议 |
|---|---|---|---|
| **B9** | **证据＝运营记忆**：行动证据留存，"每次行动优化下一次行动" | 我们的 `frontier/canon/mirror` + 收尾记账 | 已在做；可借鉴它把"**证据**"与"**结论**"分表的持久化粒度 |
| **B10** | **知识库**：查询改写 → 向量检索 → 精排 → 结果后处理 | 我们的检索＝整词/相邻二字回退（**无语义层**） | 中期可加"检索前改写"最小版（**不改冻结语义**，先记 backlog） |
| **B11** | **工具执行治理**：大输出统一兜底、**历史超大输出再次防御**、前端展示保护 | 我们的 hooks 已截断 | 可借其"**二次防御**"思路（回放历史时再截一次） |
| **B12** | **一键更新 + 更新源可配 + 原子换二进制 + 回滚点 + 保留操作者内容** | 我们的插件升级＝手工改版+重装 | 我们的插件发布可借"**原子替换 + 回滚点 + 明确保留清单**"三件套 |

## 三、明确**不学**的（避免误搬）

- **不搬它的攻击能力**（WebShell / C2 / 100+ 工具配方）进我们的产品面；
- **不搬它的 RBAC/多用户**（我们是单人工作区，属于过度设计）；
- **不把它接进阿卡夏生产链路**（仅作独立平台/参考源）。

## 四、落地下一步（我建议的顺序）

1. **B4 写成原则**（零成本，防复发）→ 2. **B5 试匹配**（小、立刻有用）→ 3. **B2 解码/嵌套检查**（补真实绕过面）→ 4. **B7 审计线** → 5. **B8 边界清单成文**；
   （B1/B10/B12 记为 backlog，待解冻或按"加固类"评估。）
