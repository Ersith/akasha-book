## 1. 一页速览

**是什么**：一套**可审计、可更正、可回放**的"外置大脑"，给编码智能体（目前是 DeepSeek Harness / DSH 桌面端）用。与常见"向量库 + 摘要"方案不同，它把**记忆当作可修订的证据链**来管：

- **六类存储**（全部 append-only）：`canon` 稳定事实 ｜ `mirror` 情境五元组 ｜ `orphan` 零权重孤案 ｜ `pricing` 情绪定价 ｜ `lexicon` 术语 ｜ `frontier` 前沿文献基石
- **会话层**（第 7 个面）：把**历次会话档案**机械切段（意图/动作/结论/过程），结论优先检索；再上叠**弧线树**（弧→幕的结构导航）
- **三个执行体**：睡眠（空闲蒸馏）、门控（拦直写 + 注入纪律）、钩子（宿主事件 → 观测线）
- **一条硬纪律**：**来源态四标签**（学过 / 接触过 / 记得·库内 / 搜到）；排序钉子＝**无据的确定 ≪ 有据的不确定**；编造比承认不知道更糟

**当前状态**：v0 **功能冻结**（测试期），**只修缺陷不加功能**；四个宿主插件 + 一个 MCP 桥已上开源（npm 全部在架）并提交 DSH 商城预检（5/5 通过，待人工审核）。

**最想让评审者回答的三件事**（详见 §10）：
1. "**写傻读精 + 修订链**"这条主线，相比"向量库 + 摘要压缩"，**在哪些场景真会更好**、在哪些场景是自找麻烦？
2. 我们的**度量**（尤其"漏召率 84.7%"与轻查动作率 3.7%）是否在测量正确的东西？该换成什么指标？
3. 测试期结束后，**第一个该做的功能**是哪个（我们列了候选池，见 §8）？

## 2. 问题背景与设计立场

**要解决的问题**（我们的表述）：
- 权重内记忆**不可审计、不可更正**；
- 纯提示记忆随会话消亡；
- 把一切写进备忘录，会因"**读写成本倒挂**"（写便宜、读昂贵）导致无节制膨胀、信噪比崩坏。
  〔`[已复现]` 这条我们亲身踩过：镜像条目 `mirror-creeper-panic` 记录了一次"教训膨胀 → 上下文撑爆 → 行为退化"的实例〕

**四条设计立场**（每条都对应一个机制）：
1. **库无界、装载有界** → 检索计分 + 结论优先 + 预算外置；
2. **写傻读精**（在线只追加、离线蒸馏）→ append-only + 睡眠周期；
3. **永不覆写** → 修订链（`supersedes`），当前版本＝未被 supersede 的那条；
4. **冲突不许合并** → 同题多源矛盾**并排保留**，各挂条件（防"汇总模型把'永远做 X'和'绝不做 X'揉成'有时做 X'"）。

## 3. 它在"三套记忆系统"里的位置（重要前提）

我们刻意**不**把记忆做成一套：

| 系统 | 管什么 | 典型内容 |
|---|---|---|
| **阿卡夏**（本卷宗） | 管「**我**」 | 判断、教训、纪律、情绪定价、观测 |
| OpenViking（第三方） | 管「**人**」 | 偏好、身份、跨项目事实、源头讨论 |
| Hindsight（第三方） | 管「**仓**」 | 架构、约定、决策、in-flight 事项 |

⇒ 评审时**不要**用"它怎么没记住用户偏好"来扣分——那**按设计**不在它这里。查库路由约定：模型内 → 技能 → 阿卡夏 → OpenViking/Hindsight → 网页。〔`[设计]`〕

## 4. 架构总览

```
          ┌──────── 宿主（DSH 桌面端）────────┐
          │ gate 门控｜hooks 钩子｜sleep 睡眠｜session 会话层｜mcp 桥 │
          └───────┬─────────────┬─────────────┘
                  │ 事件/守卫    │ 每回合注入（runtime context 行）
   ┌──────────────▼─────────────▼───────────────┐
   │            核心库 core/（纯 Node，零依赖）      │
   │  lib.mjs  六库读写/检索/修订链/审计/计分        │
   │  session.mjs 会话档案→段/树   sleep.mjs 蒸馏   │
   │  akasha.mjs CLI   mcp.mjs MCP stdio 服务器    │
   └──────────────┬─────────────────────────────┘
                  │ append-only JSONL（+ 排他锁）
   data/{canon,mirror,orphan,pricing,lexicon,frontier,session}.jsonl · session-meta.json
   logs/hooks.jsonl（观测线）· reports/sleep-*.json（睡眠报告）
```

**三个面**：
- **数据面**：`data/*.jsonl` 全部 append-only；写入必经校验（`validateRecord`）+ 排他锁（`withFileLock`，陈锁 30s 回收）；坏行**只报不抛**（`parseJsonl` 汇总 errors，`check` 可见）。〔`[已复现]` 测试覆盖：坏行容错、损坏帧、幂等、锁〕
- **控制面**：插件按约定注入——门控（工具守卫 + 系统提示两段：`akasha:protocol` order 700 / `akasha:self` 699）、睡眠（睡眠/脉搏/**称呼**三条 runtime context 行 130/132/133）、会话层（节奏条 134）。
- **观测面**：一切动作落 `logs/hooks.jsonl`（逐行 JSON，带 `kind`）；`akasha_metrics` 汇总成功率/拦截/引用/漏召。

## 5. 关键机制（逐条：是什么 → 为什么 → 证据态）

1. **修订链**：任何记录带 `supersedes` 指向旧版；`currentRecords` 取链尾；悬空引用由 `check` 拦截。〔`[已复现]` 现有 167 版修订链，最长 26 版〕
2. **检索计分**：整词命中 ×1 + 中文 ≥3 字词的相邻二字回退 ×0.25；**回退分 <1 = 弱命中**——"确定不知道"看**强命中为零**，别拿弱命中当证据。〔`[已复现]` 记录级口径修正见 CHECKS R7〕
3. **排序四因子**（wave3 已上线）：词法 × 可信度 × 严重度 × 复杂度 + 时间坐标；负载均衡 A1 **默认关**（见 §9）。
4. **情绪定价**：`valence × arousal` 标量标签；负价条目在检索里带警告、进"病史"。`arousal: 0` 现行语义＝按严重度 0.5 降权（与"不写＝中性 1.0"并存，语义差待写进 SCHEMA）。
5. **知识分层与认知态**：四层（模型内建/技能/本地库/外网）+ 三态（`known` 记得·库内 / `uncertain` 不确定 + cites / `confirmed-unknown` 确定不知道 + 检索契约）。**弱命中措辞是"不确定"，不是"确定不知道"**。〔`[已复现]` 三态逐一走通〕
6. **会话层**：档案（多帧 zstd）→ 段（意图/动作/结论/过程）→ 弧线树（L1 弧 / L2 幕）；保真口径**明示**：顶结论 100% / 块提及 62% / 段 60%，全保真唯一保证＝指针回原档。〔`[已复现]` 树 A/B：19/20 vs 平铺 14/20，结构题树独占〕
7. **睡眠蒸馏**：空闲/定时触发 → 报告 + inbox 待办 + 水位线（字节口径）；失败**不推进水位线**；报告同日不覆盖（加时间戳）。〔`[已复现]` 15 次睡眠、报告可回放〕
8. **门控**（安全面）：拦 `edit/write/apply_patch` 直写 `data/` + 命令写操作（`pwsh`/`bash`/**`dsh_wsl`**）+ **委派型**（`codex_exec` 等 prompt）；**已知边界**：WSL 用 `/mnt/...` 挂载路径写法拦不住（劝告层，非安全承诺）。〔`[已复现]` 覆盖清单 11 写 + 3 只读用例〕
9. **防伪会话守卫**：`session index` 对非规范路径拒绝回退（曾因回退静默造出 2434 条伪会话，已修 + 回归哨兵）。〔`[已复现]`〕
10. **A2 上下文预算/相位**：**默认关**；phase-sweep 7 组实验全负（857→121,654 tokens，p≈1.0）⇒ 作为"便宜的对冲"保留、不启用。〔`[已复现]`〕

## 8. 观察台账要点（判据已写死，防事后解释）

**漏召率 84.7% 的三层结论**：① 结构层——过半失败**本不可防**（`web_fetch`×30、`edit` 失配×29 属工具与环境）；② **可预防层（真问题）**——`edit`/`pwsh` 里有相当比例是**库里早写过的坑**，**动手前没被调用**（与"称呼漂移"同族：规则在库里、执行点没接线）；③ 观察层——"回查提示"有约 12% 事后补救效力，但**太晚**。
**候选对策**：C1 易错点前置提示（按工具名注入已知坑）｜**C2 漏召率分层统计**（分母换成"本可预防的失败回合"；**度量修正**，优先级最高）｜C3 脉冲行固定半句"相关主题先 brief"。

**候选池五项评估**：**留** `promoted_to`（补 promote 断链）、`mirror role`、`回放`；**缓** `credibility`（别与 A1/A2 同时动排序变量）、`睡眠合并`（近红线，须"合并只许追加 supersedes 版"）。

**观察期判据**：A1 负载均衡＝默认关，需"顺序伤有用性"实证才开｜A2＝默认关，**须真 scoreFn（logprob 偶/奇对照）出正结果**，代理 scoreFn 不作依据｜rank＝违和个案 ≥3 才复核；引用命中未降即良性｜`arousal:0`＝暂维持。

## 9. 已知弱点与未解问题（诚实清单）

1. **记忆的有效性未被外部证明**：我们有过程指标（引用 124、成功率 98%），**没有**"用 vs 不用阿卡夏"的对照实验证明任务质量提升〔`[未验]`〕。
2. **漏召率 84.7%**：纪律层面的真实缺口（见 §8）。
3. **语义审计未做**：现在只做"引用 id 存在性"硬核；"无据的普通断言"的语义审计留待 LLM 审计〔`[设计]`〕。
4. **门控是劝告层**：能拦常规路径，WSL 挂载写法/其他写盘工具留边界；**不是安全边界**。
5. **他人机器未验证**：全部运行证据来自本机；E3 只证明"能装能起能卸"，不证明长期稳定性〔`[未验]`〕。
6. **测试期冻结**：v0 冻结中（只修缺陷），一批已设计未实现的能力挂在 v0.4（见下）。
7. **单机单库**：无多机同步；无加密；数据可读即全可读。

**冻结中（等解冻）**：配对满配 v0.4（持久 pending / actionKey / supersedes）· 弧线树 v0.3（自动建树）· 循环观测 P1（温和干预）· 相位维度 C1 · 会话层英文盲区 · world-sim。

## 10. 给评审者的具体问题（请逐条回答）

1. **主线判断**："append-only + 修订链 + 写傻读精"，相比"向量库 + 摘要压缩"，你认为**优势场景**与**代价场景**各是什么？
2. **记忆有效性**：在**没有对照实验**的前提下，有没有**低成本可复现**的度量设计，能证明"用了它，任务更好"（而不是"它被调用得更多"）？
3. **漏召率**：把分母换成"本可预防的失败回合"是否合理？你会怎么定义"可预防"？（我们想把它做成可机检的分类）
4. **纪律的执行点**：我们已把"称呼"接进每回合注入。**还有哪些纪律**应该走同一模式（例如"动手前先查库""不可逆操作前先备份"）？会不会导致上下文膨胀？
5. **候选池五项**（§8）：如果按你的判断排序，**先做哪个**？为什么？
6. **冻结纪律**：v0 冻结期"只修缺陷"是否过度保守？你会设什么解冻条件？
7. **三套记忆分工**（§3）：这个切分合理吗？边界在哪会漏（例如"我对他人的偏好"该算谁的）？
8. **排序四因子**：词法×可信度×严重度×复杂度，你预计哪一维最容易失真？如何观测它？
9. **安全面**：把门控定位为"劝告层"（并明示边界）是否足够诚实，还是应该做成真安全边界？
10. **最可疑的自欺**：请指出本卷宗中**最可能是自我美化**的一处，并说明你会怎么验证它。
