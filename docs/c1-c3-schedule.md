# C1 / C3 设计计划（待评审 · v1）

> 一句话：**把"动手前先查"从一个自觉，接成两个执行点**——C1 在**动作前**给坑提示，C3 在**断言前**要事实出处。
> 依据全部来自 2026-10-10 的实测；本计划**待外部评审**后再动代码（C1/C3 属功能，需解冻授权）。

## 0. 为什么是这两件（而不是继续 A/B）

| 实测结论（有出处） | 推论 |
|---|---|
| **可预防漏召率 91.2%**（回合级，34 条可预防里漏 31）· **会话级 100%**（3 个可预防会话整段无一次事前查库）——`docs/observation-ledger.md` §1/§15 | 失败与"知不知道"无关，**与"做没做"有关** |
| 补料已到位：5 条**可执行**条目（`edit` 失配 / `read` 越界 / `rg` exit 2 / 未知工具名 / 宿主方法）+ `RECALL_TRAP_MAP` 覆盖 **11** 工具 | 知识够了 ⇒ 缺**执行点** |
| A/B 第二批：唯一有效证据＝**库里的本机事实可被检索命中并被引用**（B01 出处 `canon-npm-publish-20261010-r1`、B04 出处 `canon-address-drift-fix-20261010`；关臂同题全失且**未编造**） | 记忆的**可达性**成立；但"用了更好"无因果证据 ⇒ **不再靠 A/B 取信**，改用过程指标 + 自然实验 |

## 1. C1｜易错点前置（pre-flight hint）

**触发（可机检、无语义推断）**：即将调用工具 `T` 时，满足两条即触发一次：
1. `T ∈ RECALL_TRAP_MAP`（已有 11 个工具：pwsh/bash/edit/write/read/grep/dsh_wsl/codex_exec/apply_patch/multi_tool_use.parallel/cordis_inspect_query）；
2. `T` 在**近 24h** 内有 `ok:false` 记录（hooks 线可查）。**不做**语义判断、不做全文注入。

**输出（一行，≤80 字）**：`[坑前提示] <T> 前先 <动作> —— 条目 <id>`（例：`[坑前提示] edit 前先 read 原文再改 —— canon-trap-edit-context-mismatch`）。

**落点**：`@local/akasha-sleep` 的 context 行（order **135**，渲染路径已验证、失败安全）。备选：gate 的工具前置钩子（更强但更侵入，**v1 不用**）。

**硬约束（外部评审要求：短·可关·防膨胀）**：
- 开关：`preflightHints: false` 一键关闭 ⇒ 关闭后**零可见变化**；
- 去重：同一坑 **30 分钟**内不重复（`hintCooldownMin: 30`）；
- 上限：每回合最多 **1** 条（`hintPerTurnMax: 1`）；**只提示，不阻断**。

**记录与验收**：
- hooks 记 `preflight` 事件（触发工具 / 展示条目 / 之后同工具是否仍失败）；
- 验收①关闭零变化；②触发率、误触发率（触发后无失败）可机检；③**连续 7 天观察"同坑复发率"**：目标从基线下降（基线＝`grep`/`read`/`edit` 类近 5 天 32 次未查库）。

## 2. C3｜断言前必查（stateful-fact gate）

**触发（可机检）**：回复文本包含**状态性关键词**（已发布 / 未发布 / 已安装 / 已过审 / 版本 / 开关 / 存在与否 / 状态）**且**本回合**没有**任何查库或取证动作（无 `mcp__akasha__*` 只读调用、无 `akasha` CLI 查库、无对应的取证命令）⇒ 触发。

**输出（一行，≤80 字）**：`[断言提醒] 这是状态性事实——先查再断言。上次相关结论：<一句话>（出处 <id>）`；若无上次结论则只提醒。

**落点**：同 C1 路径（回合前/回复前轻量版）；**只提醒，不阻断**。

**开关/去重**：`statefulGate: false`；同一话题 30 分钟去重；每回合 ≤1 条。

**记录与验收**：
- hooks 记 `stateful-reminder`；
- 验收①关闭零变化；②触发与命中可机检；③以 **矛盾式漏召（H5）**计数观察——目标是**把 npm 那类"同一会话内自相矛盾"压到 0**（自然实验口径，**不再做 A/B**）。

## 3. 为什么这两件能对症（如实说明局限）

- 它们**不提高"知道"**（知识已在库），而是**在动作/断言那一瞬把库拉进来**——正对 91.2% 那张表的成因；
- **不保证有效**：若提示被忽略，指标不会动；因此验收以**观察指标**为准（不是"功能上线即成功"）；
- **风险**：提示变噪声（已用去重+上限压住）；与既有注入行冲突（独立 order、失败安全、可关）。

## 5. 风险与回滚

- 两枚开关单点关闭；纯渲染路径，**数据零影响**；回滚＝撤插件版本（`-h1` 保留前版）。
- 不新增数据文件、不改 schema；若 7 天后指标无变化 ⇒ 结论写"**无效**"并入 canon（同 A/B 的处理）。

## 7. 评审后修订（Claude，2026-10-10；**全部采纳**）

> 评审前置判断：**"方向对，可以按这个解冻写；『知识够了缺执行点』这个判断成立。"**

| # | 评审意见 | 落实（v2 定稿） |
|---|---|---|
| 1 | **C1 触发偏松**：edit 每天几十次会"每回合都响" | 触发加**两个前置**：① **本回合尚未发生查库/取证动作**；② 24h 失败改为「**近 N 次同工具失败 ≥ 1**」（N 初值 20，可调）。 |
| 2 | 每回合 ≤1 够紧；**同回合都命中时 C3 优先** | 定为：**C3 > C1**；C1 顺延下一回合，**或**与 C3 并入同一行（分号分隔，仍 ≤80 字） |
| 3 | **C3 词表先窄**，别一开始铺开 | v1 词表仅 6 项：`已发布/未发布` · `已安装/未安装` · `版本号` · `开关状态` · `存在与否` · `已过审/未过审`；漏报再加 |
| 4 | **普通只提醒；不可逆要强阻断，但别塞进 C1/C3** | 采纳：覆盖/删除/`git push`/`--hard` 这类**放到门控（gate）里做强阻断**，C1/C3 仍只提醒 |
| 5 | 7 天可以，**但要写基线**，别口头对比 | 加**基线期**：观察前 **5–7 天**先跑同口径指标（不开启提示）⇒ 观察期与基线**同口径对比**，写进结论 |
| 6 | **别合并 C1/C3**；先上 C1，C3 紧随 | 采纳：C1 先（`edit` 失配是最大类），C3 紧随；两者独立开关、独立 order |
| 7 | 补充：提示行**带条目 id 很好** | 保留 `—— 条目 <id>`；并**加"关闭时 hooks 也不写假触发"**（`preflightHints:false` ⇒ **不记** preflight 事件） |
| 8 | 补充：观察脚本**会话级与回合级分开报** | 观察输出固定两栏：**会话级同坑复发**（同一会话内重复踩同坑的次数）与**回合级同坑复发** |

**据此的 v2 定稿要点（与 §1/§2 的差异）**：
- C1 触发 = `T ∈ RECALL_TRAP_MAP` ∧ `近 20 次调用 T 中有失败` ∧ `本回合尚无查库动作`；
- 优先级 = `C3` 先于 `C1`；同一回合两条命中时**并一行**（分号分隔）；
- C3 词表 = 上述 6 项（**先窄**）；
- **不可逆强阻断归 gate**（不在本计划实现，另立）；
- 基线期 **5–7 天** → 观察期；指标**两级分列**；
- 关闭开关 ⇒ 提示与事件**双停**（不产生假数据）。

**执行前提**：解冻授权（属功能）。**先做 C1**，C3 紧随。

## 8. 实施记录（C1 · 2026-10-10，解冻后）

- **实现**：sleep 插件新增 context 行 `akasha:preflight`（order 135）——取**近 30 分钟最近失败的工具**，若其在 `RECALL_TRAP_MAP` 内 ⇒ 渲染一行 ≤80 字：`[坑前提示] <工具> 前：<动作> —— 条目 <id>`；**同工具 30 分钟去重 · 每回合 ≤1 条 · 只提示不阻断**；`preflightHints:false` ⇒ **提示与事件双停**（不写假触发）；事件 `kind=preflight` 落 `logs/hooks.jsonl`。
- **如实标注的近似**：context 行在**回合开始**渲染，此刻不知道本回合会调用什么工具 ⇒ v1 用“最近失败的工具”作**预提示**；“本回合尚未查库”这一前置在渲染时不可判定（弱化为去重 + 上限）。
- **验证（本轮）**：双树语法 ✓ · sleep 自测 exit=0 · 核心套件 **140/140** · 版本 `1.5.5-h1 → 1.6.0-h1`（仓 1.6.0）· tgz 已打包 · **install_bundle 成功（restart-required）**。
- **待办（不得省）**：① **C1 自测断言**（去重 / 映射表外不提示 / 关闭双停）——本轮未补，**列为下一步第一件**；② 重启后**端到端验证**（下一回合若近 30 分钟有失败，应见 `[坑前提示] …` 行）；③ **C3** 紧随。
