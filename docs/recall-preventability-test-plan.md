> 目的：**定阈值前先定性**——哪些失败本来能靠库避免（"可预防"），哪些不能。没有这个集合，"漏召率"这个分母就是错的。

> 提交物：三档证据表 + 分布 + **阈值推导** + 复核包。

## 2. 术语与判定口径（**先写死，防事后解释**）

- **失败回合**：hooks 线里"同一会话窗口内（相邻两条 turn-end 之间）的**首次**失败"（与 `metrics` 口径一致，见 `lib.mjs:recallSignals`）。
- **理想问句**：一个**站在失败发生之前**的、合格操作者会问库的问题（例：`pwsh 引号 转义 单引号内嵌`）。**每条失败允许最多 2 次改写**，改写过程留痕。
- **强命中**：`lookupDetailed` 命中分 ≥1（＝至少一次整词命中）**且**判断者认为内容与本次失败相关（两步缺一不可）。
- **覆盖（判定核心）**：命中条目的 `claim`/行为**直接给出该错误的成因或修复手法**。
  - ✅ 覆盖（正例）：失败＝pwsh 单引号内嵌单引号报错；命中条目明确写"不要在单引号字符串里放单引号"。
  - ❌ 不覆盖（反例）：命中条目只是**主题相关**（如"某次 pwsh 命令失败过"），没有成因/手法。
  - ⚠️ 存疑：只能给出**间接线索**（如条款提到同类工具但未给手法）→ 归"存疑"，**不并入可预防**（宁紧勿宽）。
- **结构性不可预防**：网络/环境/宿主缺陷（`web_fetch`、`web_search`，及任何**失败与库内容无因果关系**者）——**永不入可预防集合**（沿用 `RECALL_STRUCTURAL_TOOLS`）。

## 4. 方法（五步；**前两步刻意"盲"**）

1. **取证**：导出 59 条失败记录（工具、时间、会话、上下文摘要）→ 冻结成 `_scratch/prevability/cases.jsonl`（含 sha256，防改动）。
2. **造问句（盲）**：只看"失败前的上下文"，**不看**后续发生了什么，写出理想问句（记录改写次数）。
3. **机器初筛**：对每条问句跑 `lookupDetailed`，导出 top-5 命中（id、score、strong、claim 摘要）。
4. **人读判定（盲 + 双评）**：判定者按 §2 准则给"覆盖 / 不覆盖 / 存疑"；**至少两个独立判定**（人 + 第三方模型，或我 + Claude），**不一致者进仲裁集**；判定者不看"我事后是否补救"（防结果污染）。
5. **汇总**：出三档表 + 分布 + 不一致率 + 阈值推导（§7）。

## 5. 输出物（交付形态）

1. **三档证据表**（`prevability-report.md`）：每条含 `case → 问句 → 命中 id/score → 判定 → 理由一行`；
2. **分布表**：按工具 / 按主题（引号类、编码类、路径类、匹配失配类…）；
3. **不一致集**（双评分歧）+ 仲裁记录；
4. **阈值推导**（§7）；
5. **复核包**：随机抽 10 条（含 3 条"存疑"）**原样**交给评审者盲判，核对一致率（**一致率 <70% ⇒ 判定准则要改，先别定阈值**）。

## 6. 偏差与威胁（写给评审者挑刺）

| 威胁 | 说明 | 缓解 |
|---|---|---|
| **后见之明偏差** | 判定者已知道"答案"（失败怎么解决的） | 步骤 2/4 盲化；判定者只看"失败前"的信息；随机抽 10 条做第三方盲判 |
| **判定漂移** | 59 条判定过程中标准会漂 | 先判 10 条 → 固定"准则卡" → 再判完；记录中途是否改口径 |
| **度量缺口** | 未识别路径的查库（如 `dsh_wsl`）此前不计召回 | 已补入 hooks 分类；本测试**不依赖**该计数，独立取证 |
| **样本量小** | 59 条（日 5–19） | 全量纳入（不抽样）；结论按**工具分层**汇报，不给"总体统计显著性"的假承诺 |
| **时间窗偏差** | 全部来自 10-06~10-10，库与习惯都在变 | 记录每条 case 的日期；对"最近 2 天"与"更早"分组对比 |
| **我判我自己** | 判定者＝库的作者 | 双评 + 第三方盲判抽检；争议进仲裁；**一致率不达标则退回改准则** |

## 7. 阈值怎么"长出来"（不拍脑袋）

1. 得到**可预防集合 P**（该算的 case）与其中**实际未查库的条数 M**；
2. 定义 **可预防漏召率 r = M / |P|**（当前粗口径下是 90.9%，P 更紧后会变）；
3. 阈值不由 r 反推，而由**代价**推：
   - 记单次"同坑复发"的平均代价 c（返工轮数 / 时间；可从历史返工统计）；
   - 设我们能接受的**单位时间返工上限** R；
   - 目标：`r ≤ 1 − (可接受未被防住的次数 / |P|)`——**用"还能容忍漏掉几次"来表达**，比"拍一个百分比"诚实；
4. **敏感性**：`|P|` 会随新坑条目增长 ⇒ 结论是"**给定当前库**，r 应为 X；每次库显著增长后复测"。

**Claude 对 §9 八问的答复（要点）**：覆盖准则够硬、存疑宁紧不错；盲化可行但**必须模板约束**；威胁补"会话内非独立 / 库时序泄漏 / 问句改写次数的选择偏差"；**用"可容忍漏掉次数"定阈值更诚实**（可并行报百分比便于沟通）；存疑单列不折半；**A/B 重犯更强但贵**——本法先定分母，有余力再抽"可预防子集做关闭臂回放"。**结论**：可开干；优先落地取证脚本、快照、双评准则卡，阈值等三档表出来再定。

**关键结论（推翻初筛）**：机器初筛报"16/49 有合法强命中"，**精判首批 15 条的真阳性为 0**——强命中**≠**覆盖，初筛精度极低（这正是"双评"存在的意义）。

让"可预防集合"**长出来**，再谈漏召率与阈值。

**三档表（首批口径）**：该算 0 · 不该算 15（其中结构性 4 / 不覆盖 5 / 缺口 6）· 存疑 0。
