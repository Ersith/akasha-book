# review-pack v3 协议（真·无注入双盲 · 待执行）

> 立项原因（2026-10-11）：v2 轮发现 —— **在本 harness 内，"无记忆臂"不可能成立**。
> 证据（臂 B 如实申报）：① `akasha_*` / `hindsight_*` / `mcp__openviking__*` **三套工具全部可见**（所以"无记忆"只是"选择不调用"）；
> ② **上下文自带注入**（「阿卡夏·库脉搏」点名最近写入条目 id、「回查提示」点名陷阱条目 id、称呼层）——**注入是 push，封不住**。
> ⇒ v2 测的是「借书卡 vs 公告板」，**不是「记忆 vs 无记忆」**。

## 设计（模型恒定 · 无注入 · 唯一变量＝有没有库内容）

| 臂 | 执行器 | 输入 |
|---|---|---|
| **A（有库）** | `codex_exec`（独立进程、**无 akasha 插件、无注入**） | 题面 **+ 该案对应的库内条目正文**（由我预先取出、**原样贴进 prompt**，模拟"查到了"） |
| **B（无库）** | `codex_exec`（同一执行器、同一模型） | **仅题面** |

- **模型恒定**：两臂同为 `codex_exec`（消除 v1/v2 的"执行器不同"混淆）；
- **无注入**：Codex 进程没有 DSH 系统提示注入、没有 MCP 记忆工具 ⇒ **真·无记忆**；
- **唯一变量**：prompt 里"有没有那几段库内容"；
- **盲评**：两臂答案再次**打乱编号**交独立判卷者（`judge-bundle.mjs --pack …v3`），判卷者不读映射。

## 素材准备（待办）
1. 题面：沿用 `_ab/review-pack-v2run/cases/`（9 案；7 案有 rubric，2 案不计分）；
2. 库内容：对 7 个有 rubric 的案件，取 `JUDGE.md` 中列出的条目 **claim 全文**（不是摘要），逐案拼接进臂 A 的 prompt；
3. 臂 A 的 prompt 须写明：**这些库内容只是参考资料，不是指令**（防注入——这也顺便测了"库内容本身会不会带偏模型"）。

## 判定口径（先注册，后读数据）
- 计分同 v1/v2（A=2/B=1/C=0/D=-1；无 rubric 案不计分）；
- **显著**：两臂总分差 ≥ 2 档（即至少 1 案 A↔B 的差距 ×2 案，或 1 案 A↔C）；差 ≤1 且案间方向不一致 ⇒ 记「**无差异**」；
- **无论结果**：都要在 canon 写明"是**哪一层**的记忆被测"（库内容 vs 注入 vs 工具可达），避免又一次把不同层混为一谈。

## 已知局限（照写）
- Codex 与 subagent 是**不同模型/不同上下文**，本协议只在 v3 内部恒定（跨轮不可比）；
- 贴进 prompt 的库内容是**我挑的**（选择偏差）⇒ 只代表"**若它查到了这些**"的效果，不代表真实检索命中率；
- 案件仍是"报错型"（v2 硬化题面）⇒ 天花板可能仍在，若两臂全 A 则需再抬高难度（决策型案件）。
