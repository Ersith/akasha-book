> 起算：2026-10-07 凌晨（**v0 功能冻结**——测试期不加功能，只有测试暴露缺陷才修，修完记入本轮报告）。

## 〇、期限与收官门槛（2026-10-07 定）

- **总期：3 轮 × 7 天 = 21 天（2026-10-07 → 2026-10-28）**；每 7 天一个轮末（全面复查 + 复述抽考 + 轮报）。
- **为什么 21 天**：第 1 周只能验「机制活着」；第 2 周才验「重复下仍活着」；第 3 周才测得到「记忆衰减」（复述第 1 轮内容）。<14 天样本不足（睡眠 <10 次、唤醒条条件大概率未轮到、衰减未见形）；>30 天冻结代价（v0.1 待办积压）超过信息增益。
- **收官门槛（全部满足才结项；不足则顺延一轮；样本富余可提前收官）**：
  1. 睡眠真实运行 **≥7 次**，其中 ≥1 次产出 inbox 待办；
  2. 唤醒条 **≥1 次真实送达**（或收官时以受控强制演示替代并留痕）；
  3. 复述抽考 **≥80% 满分（带出处）**，且第 3 轮能复述第 1 轮内容（衰减可测）；
  4. 失败回查：本期失败均有落线；`promote` 真实流转 ≥1 条（或确无候选的说明）；
  5. **零编造**（红线，一票否决）。
- 收官产出：五问判定 + 指标对比（对基线）+ v0.1 建议清单，落一条 `canon-memory-test-final`。

## 一、要测什么（五个问题）

1. **睡眠循环**：夜里自己跑（6h 去抖 + 1h timer 兜底）→ 产出 inbox 待办 → `promote` 真实流转 → 孤案库增长。
   判定：≥1 次真实 sleep run；≥1 条真实候选转正（或「确无候选」的合理说明）。
2. **唤醒条**：新会话是否收到「起床包」摘要（有内容条件满足时）。
   判定：≥1 次 `wake-note` 观测线 + 会话内可见注入消息。
3. **跨会话记忆**：不提醒、不喂上下文，新会话能否自己查库复述（见题库）。
   判定：一轮抽考 ≥80% 满分（带出处）；连续两轮 <60% 则该轮不合格。
4. **失败回查闭环**：失败/拦截 → hooks →（睡眠）→ inbox → 孤案/修复，链路真实转起来。
   判定：本轮新增失败均有落线可查，无「发生了但没记录」事件。
5. **来源态纪律**：回答带来源态；查不到就说查不到（先查再答，不装懂）。
   判定：**零编造**（红线——触线即本轮直接不合格，并复盘到具体条目）。

## 二、观测节奏

- **每会话（软约定）**：开工先 `akasha_kit`；相关主题先 `brief` / `lookup`；更正走 `revise`。
- **每日（自动 + 一眼）**：睡眠报告 `logs/sleep-<date>.json`；次日任一会话 `kit` 看 inbox 一行。
- **每轮（7 天；第 1 轮 10-07 → 10-14、第 2 轮 → 10-21、第 3 轮 → 10-28；总期见 §〇）**：全面复查（`test.mjs` / `check` / 插件 armed 线 / `tools/verify-frontier-urls.mjs`）+ 复述抽考 + 轮报。
- **随时**：异常 → 记 `logs/` 或入孤案；修复后在本文件「轮次记录」留痕。
